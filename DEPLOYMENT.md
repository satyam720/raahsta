# Deploy Raahsta on Render Free

The Blueprint uses **Render Free**, no persistent disk, Brevo's HTTPS email API,
Cloudinary image uploads, and your existing MongoDB Atlas database. Providers have
their own free-plan quotas; select those plans when signing up. No services are
created and no account settings are changed by editing these files.

## Render settings

1. Commit and push these changes. Never commit `config.env` or real credentials.
2. Create a Blueprint using `render.yaml`, or configure your existing web service:
   - Instance: **Free**; no persistent disk.
   - Root directory: the folder containing this app's package.json.
   - Build: `npm ci --include=dev && npm run build:js`
   - Start: `npm start`
   - Health check: `/health`
3. Set the variables below in the dashboard. Render supplies PORT automatically.
   Delete the old UPLOAD_DIR=/var/data/raahsta variable. SMTP variables are unused.
4. Save and redeploy. Changes to render.yaml do not change a manually created
   service's dashboard settings automatically.

```text
NODE_ENV=production
NODE_VERSION=24
TRUST_PROXY_HOPS=1
UPLOAD_STORAGE=cloudinary
CLOUDINARY_CLOUD_NAME=...
CLOUDINARY_API_KEY=...
CLOUDINARY_API_SECRET=...
BREVO_API_KEY=...
EMAIL_FROM=...
DATABASE=...
DATABASE_PASSWORD=...
JWT_SECRET=...
JWT_EXPIRES_IN=90d
JWT_COOKIE_EXPIRES_IN=90
MAPBOX_ACCESS_TOKEN=...
RAZORPAY_TEST_KEY_ID=...
RAZORPAY_TEST_KEY_SECRET=...
```

Keep the JWT_SECRET generated by the Blueprint, or create a strong random secret
for a manually configured service. Use your existing Atlas database to keep data.
DATABASE can be a full URI or use `<db_password>` plus DATABASE_PASSWORD. URI
credentials must be percent-encoded when they contain special characters.

## Brevo email over HTTPS

In Brevo's SMTP & API settings, create an **API key**, not an SMTP key. Set it as
BREVO_API_KEY. EMAIL_FROM must be a verified sender. Your Pug email templates and
plain-text email alternatives are retained. Production no longer connects to SMTP.
If Brevo API IP restrictions are enabled, authorize your server's outbound addresses.
Local development continues to use the EMAIL_HOST/PORT/USERNAME/PASSWORD sandbox.

Reference: https://developers.brevo.com/docs/send-a-transactional-email

## Cloudinary image storage

Create a Cloudinary account on its free plan. In its dashboard, copy the cloud name,
API key and API secret into the matching variables. Keep the secret server-side.
Uploads are signed on the server; no unsigned upload preset is required.

New images are resized locally in memory, then uploaded over HTTPS under
`raahsta/users` or `raahsta/tours`. MongoDB keeps its existing filename format.
The app serves bundled images first; new `/img/users/...` and `/img/tours/...`
URLs redirect to Cloudinary. Existing sample images therefore still work.

Previously uploaded images must be committed as public assets or migrated separately
if they only exist on your computer/old disk. A database filename alone does not
copy the image to Cloudinary. Re-uploading an account photo after deployment also works.

Reference: https://cloudinary.com/documentation/upload_images

## Network access and checks

- Add Render's outbound addresses/ranges to Atlas Network Access.
- Update Mapbox token URL restrictions to include the deployed hostname.
- Test `/health`, tour pages, login/logout, reset emails, and photo uploads.
- Restart/redeploy and confirm the uploaded photo still loads.
- Complete a Razorpay **test** payment and check the booking and My Tours.

The app waits for MongoDB before accepting traffic and closes gracefully on SIGTERM.
Free Render services can sleep when inactive, so the first request may take time.
Razorpay stays in test mode. A signed idempotent payment webhook remains necessary
before relying on browser-independent payment reconciliation for real payments.

Local commands: `npm start`, `npm run start:dev`, `npm run watch:js`,
`npm run build:js`, and `npm test`.
